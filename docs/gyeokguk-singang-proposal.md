# 월지 격국·신강신약 규칙안

> **이 문서는 제안서다. v2.3 앱의 판정에는 적용하지 않았다.**
> 사용자 승인 전까지 `rules/`에 넣지 않으며, 화면에도 나가지 않는다.
> 여기 적은 가중치·임계값은 **정설이 아니라 제품이 선택해야 할 후보안**이다.
> 용신·희기신 자동 판정은 이 문서의 범위에 넣지 않는다.

---

## 0. 왜 별도 문서로 두는가

v2.2의 판정은 “오행 개수”와 “십성 개수”가 전부였다. 격국·신강신약은 학파 차이가 커서, 코드로 옮기는 순간 **한 학파의 규칙이 정설처럼** 사용자에게 나간다. 자평명리에서도 다음 세 가지는 문헌마다 다르다.

1. 격을 월지 본기로만 잡는지, 투출(透出)을 우선하는지.
2. 득령을 오행 생조로 보는지, 12운성(장생~제왕)으로 보는지.
3. 득세를 개수로 세는지, 지장간 가중으로 세는지.

그래서 이 문서는 **판정 규칙의 후보와 근거**만 정리하고, 채택은 사용자 승인 뒤로 미룬다.

---

## 1. 월지 격국(月支格局)

### 1.1 문헌 골격

- 『자평진전(子平眞詮)』 권1 「論正官」「論財」「論印綬」「論食神」「論傷官」「論偏官」 — 월령을 기준으로 격을 세우고, 그 격에 맞는 상신(相神)을 논한다.
- 『적천수(滴天髓)』 「通神論」 — 월령과 일간의 관계를 먼저 본다.
- 『삼명통회(三命通會)』 권2 「論格局」 — 월지 본기와 투출을 함께 본다.

세 문헌의 공통분모는 **“월지(月支)가 격의 기준”**이라는 점이다. 세부 우선순위는 갈린다.

### 1.2 후보 규칙 A — 본기 우선(가장 단순)

```
1) 월지의 본기(지장간 첫 글자)를 취한다.
2) 본기의 십성으로 격명을 정한다.
   비견→건록격, 겁재→월겁격(양인이면 양인격), 식신→식신격, 상관→상관격,
   편재→편재격, 정재→정재격, 편관→편관격(칠살격), 정관→정관격,
   편인→편인격, 정인→정인격
3) 월지가 子·午·卯·酉(왕지)면 본기가 하나뿐이라 그대로 확정.
```

- 장점: 규칙이 하나고, 같은 명식이면 언제나 같은 격이 나온다.
- 단점: 투출한 중기·여기를 무시한다. 예를 들어 寅월 戊일간은 본기 甲(편관)만 보지만, 천간에 丙이 투출하면 식신격 논의가 가능하다.

### 1.3 후보 규칙 B — 투출 우선(자평진전 계열)

```
1) 월지 지장간 중 천간에 투출한 글자를 찾는다.
2) 투출이 여럿이면 본기에 가까운 것(본기 > 중기 > 여기)을 택한다.
3) 투출이 없으면 본기로 격을 정한다.
4) 월지가 子·午·卯·酉면 투출 여부와 무관하게 본기.
```

- 장점: 문헌의 ‘투출’ 논의를 반영한다.
- 단점: “여럿이면”의 우선순위가 문헌마다 다르고, 같은 지장간이라도 합·충으로 투출이 무력화되는 경우를 다루지 않는다.

### 1.4 후보 규칙 C — A와 B를 병기(화면 설명용)

- 판정은 A로 하되, B가 다르면 “월지 본기로는 정관격, 투출을 보면 식신격”처럼 **두 격을 조건과 함께** 보여 준다.
- 단정 문장은 A와 B가 일치할 때만 쓴다.

**권고**: v2.4에서 도입한다면 **C**를 권한다. v2.2의 “문장↔근거” 문제를 반복하지 않으려면, 격을 하나로 단정하기보다 `Finding` 두 개(`GEOK.BONGGI`, `GEOK.TUTUL`)를 만들고 문장이 둘을 조건으로 요구하게 하는 편이 안전하다.

### 1.5 격명 목록과 십성 대응

| 월지 본기 십성 | 격명 | 비고 |
|---|---|---|
| 비견 | 건록격 | 일간과 같은 오행·같은 음양 |
| 겁재 | 월겁격 / 양인격 | 양간이면 양인격으로 부르는 학파가 많다 |
| 식신 | 식신격 | |
| 상관 | 상관격 | |
| 편재 | 편재격 | |
| 정재 | 정재격 | |
| 편관 | 편관격(칠살격) | |
| 정관 | 정관격 | |
| 편인 | 편인격 | |
| 정인 | 정인격 | |

월지가 辰·戌·丑·未(잡기)면 본기가 土라 土일간은 비견·겁재, 다른 일간은 재·관·인으로 갈린다. 잡기월의 격은 특히 학파 차이가 크므로 **A/B 병기**가 필요하다.

## 2. 득령(得令) · 득지(得地) · 득세(得勢)

### 2.1 정의

- **득령**: 월지가 일간을 돕는가. 계절의 힘을 받는 자리.
- **득지**: 일지가 일간을 돕는가. 앉은 자리의 힘.
- **득세**: 천간·지지의 세력이 일간을 돕는가. 같은 편(비겁·인성)이 많은가.

“돕는다”의 정의가 학파마다 다르다.

| 관점 | 돕는 것으로 보는 것 | 문헌 |
|---|---|---|
| 오행 생조 | 같은 오행(비겁), 나를 낳는 오행(인성) | 자평진전 계열 |
| 12운성 | 장생·목욕·관대·건록·제왕·태·양 | 삼명통회 계열 |
| 통근 | 지지에 일간의 뿌리(같은 오행)가 있는지 | 적천수 계열 |

### 2.2 계절 왕상휴수사(旺相休囚死)

월지의 계절 기운을 오행에 대응시키는 표다. 이 표 자체는 문헌 공통이다.

| 계절 | 월지 | 왕(旺) | 상(相) | 휴(休) | 수(囚) | 사(死) |
|---|---|---|---|---|---|---|
| 봄 | 寅卯辰 | 목 | 화 | 수 | 금 | 토 |
| 여름 | 巳午未 | 화 | 토 | 목 | 수 | 금 |
| 가을 | 申酉戌 | 금 | 수 | 토 | 화 | 목 |
| 겨울 | 亥子丑 | 수 | 목 | 금 | 토 | 화 |

- 득령의 가장 보수적인 정의: **월지 오행이 일간과 같거나(왕) 일간을 낳으면(상) 득령**.
- 辰·戌·丑·未는 계절의 끝(土)이라 土를 왕으로 보는 학파와, 해당 계절 오행을 왕으로 보는 학파가 갈린다.

### 2.3 후보 판정안

#### 후보 1 — 개수 세기(가중치 없음)

```
득령 = 1 if 월지 오행 ∈ {일간 오행, 일간을 낳는 오행} else 0
득지 = 1 if 일지 오행 ∈ {일간 오행, 일간을 낳는 오행} else 0
득세 = 1 if (비겁+인성 개수) > (식상+재+관 개수) else 0
신강 = 득령 + 득지 + 득세 ≥ 2
신약 = 득령 + 득지 + 득세 = 0
중화 = 나머지
```

- 장점: 가중치를 만들지 않아 “정설인 척”할 여지가 없다.
- 단점: 3요소가 같은 무게라, 득령의 계절 효과를 과소평가한다는 비판이 가능하다.

#### 후보 2 — 문헌형 가중(제품 규약으로 명시)

```
득령 2점, 득지 1점, 득세 2점  (합 5점)
신강 ≥ 4, 중화 2~3, 신약 ≤ 1
```

- 장점: 득령·득세를 중시하는 학파의 직관과 가깝다.
- 단점: 2·1·2라는 숫자는 어느 문헌에도 없다. **제품이 정한 값**임을 화면·약관에 명시해야 한다.

#### 후보 3 — 12운성 보조

```
득령 = 월지에서 일간의 12운성이 장생·목욕·관대·건록·제왕·태·양 중 하나
```

- 장점: 계산이 이미 코드에 있다(`stageOf`).
- 단점: 12운성은 왕쇠를 보는 보조 지표이고, 오행 생조와 결론이 다를 때가 많다.

**권고**: v2.4에서 도입한다면 **후보 1을 기본**으로 하고, 화면에는 “득령/득지/득세 중 몇 개”만 보여 준다. 점수·가중치는 사용자 승인 없이 넣지 않는다. 후보 2를 쓰려면 별도 동의와 화면 고지가 필요하다.

## 3. 신강·중화·신약 판정의 금지선

1. **점수를 정설처럼 쓰지 않는다.** 2·1·2 같은 값은 제품 규약 라벨을 붙인다.
2. **용신·희기신을 자동 판정하지 않는다.** 억부·조후·통관·병약 등 유파가 갈리고, 같은 신강이라도 용신이 정반대로 나오는 사례가 많다.
3. **격국과 신강을 한 문장에서 단정하지 않는다.** “정관격 신약”처럼 두 판정을 합쳐 단정하려면 두 Finding을 모두 requires로 갖는 문장만 허용한다.
4. **합·충으로 득령이 바뀌는 경우를 자동 보정하지 않는다.** 월지가 합으로 묶이거나 충을 받는 경우는 문헌마다 해석이 갈린다. v2.4에서는 “월지가 午와 六合” 같은 사실만 Finding으로 두고, 득령 점수를 깎지 않는다.

## 4. 도입 시 필요한 것 (승인 후 작업 목록)

1. `rules/geukguk.js` — 후보 A/B/C 중 선택된 규칙, `Finding` id는 `GEOK.BONGGI.*`, `GEOK.TUTUL.*`.
2. `rules/strength.js` — 후보 1(개수) 기준, `STRENGTH.DEUKRYEONG`, `STRENGTH.DEUKJI`, `STRENGTH.DEUKSE`, `STRENGTH.VERDICT`.
3. `content/` — 격·신강 문장은 **단정 금지**. `requires: ['GEOK.*','STRENGTH.*']`를 모두 요구하고, “제품 규약” 문구를 문장 안에 포함.
4. 테스트 — 최소 30명식에 대해 (a) 격 A/B 결과와 근거, (b) 득령·득지·득세 각 값, (c) 같은 명식 결정성, (d) 격·신강 문장의 requires 충족.
5. 화면 — 판정을 보여 줄 경우 “학파에 따라 다를 수 있어요” 고지와 근거 칩을 함께 낸다.
