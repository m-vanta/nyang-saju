# 유료 7챕터 정의

> 이 문서는 **유료 결과물의 설계도**다. 실험 하네스(`tests/ai-compare/`)의 8개 비교 섹션이
> 이 7챕터로 조립된다. 각 챕터는 "무료에서 이미 본 것"과 "돈을 내고 새로 얻는 것"이
> 문장 단위로 갈려야 한다. 무료의 반복이면 유료가 아니다.

## 0. 무료 / 유료의 경계

| 구분 | 지금 무료가 주는 것 | 유료가 새로 줘야 하는 것 |
|---|---|---|
| 정의 | 팔자 고양이 유형 한 줄, 오행 최다·결핍 한 줄 | 그 구조가 **왜** 그렇게 생겼는지(월령·통근·지장간·십성 두 층) |
| 팩폭 | 한 문장 | 팩폭이 **어느 장면에서** 반복되는지, 조건 |
| 성향 | 대표 성향 3개(라벨+한 문단) | 상반된 두 성향이 **언제 갈리는지** |
| 돈·일 | 주제별 한 문단 | 돈이 들어오는 경로와 새는 지점, 맞는 환경/피할 환경 |
| 시기 | 올해 세운 한 줄 | 지금 대운·세운 구간의 방식과 다음 구간의 준비 |
| 사람 | (없음) | 일주 관계로 본 인연 유형, 곁에 둘 기운 |
| 부적 | (없음) | 명식이 각인된 개인 부적 이미지 + 한마디 |

원칙: **무료는 "당신은 무엇인가", 유료는 "왜 그런가 · 언제 그런가 · 무엇을 하면 다른가"**.

## 1. 챕터 ↔ 실험 섹션 ↔ 현재 앱 콘텐츠

| # | 챕터 | 실험 8섹션 | 현재 앱 콘텐츠(참고) | 조립 방식 |
|---|---|---|---|---|
| 1 | 나도 몰랐던 나 | §01 천기팩폭 + §02 대표 성향 | 무료 팩폭·대표 성향, 유료 성향 상세 | 2섹션 순차 |
| 2 | 반복되는 나의 패턴 | §04 반복되는 행동 패턴 | `buildPatterns` 3축 | 그대로 |
| 3 | 사랑할 때의 나 | §05 연애운 (+§03 중 관계 축) | 본편 01~03 중 고른 운세 | 1섹션 + 조건 |
| 4 | 돈과 일, 나의 방식 | §06 재물운 + §07 직업운 | 본편 02 돈과 일의 흐름 | 2섹션 병합 |
| 5 | 지금 내 인생의 흐름 | §08 대운 및 올해 운세 | 본편 04 타이밍 | 그대로 |

| 7 | 냥도사의 천기부적 | (없음 — 코드 생성) | 천기부적 PNG | AI는 문구 후보만 |

## 2. 챕터별 정의

### 챕터 1. 나도 몰랐던 나

- **무료 대비 새 정보**
  - 유형 이름 하나가 아니라 **겉으로 쓰는 십성(표면)** 과 **지장간까지 센 십성**이 다르다는 구조.
  - 월령이 만든 계절의 결(왕상휴수사)과 통근의 유무가 어떻게 다른 층을 만드는지.
  - 팩폭 1문장이 반복되는 장면 1~2개(회의, 가까운 사람과의 대화 등) — 근거 있는 장면만.
- **필요 입력**
  - 필수: `chart`(간지·오행 개수·표면 십성), `analysisData.monthCommand`, `deukryeong`(4판독), `roots`, `tenGodFacts`(두 집계), `hiddenStems`, `deukji`, `elementFacts`.
  - 선택: `saenggeuk`, `hapchong`(성격 문장에 관계를 붙일 때만), `paidTraits` 카탈로그(폴백).
  - 없으면 비운다: `analysisData` 가 없으면 §02를 `unavailable` 로 두고 폴백 문장으로 대체.
- **생성 조건**
  - 문단 3~5개. 첫 문단은 팩폭(짧게), 이후 2~4문단은 구조 설명.
  - 문단마다 서로 다른 축 1개 이상(월령 / 통근 / 지장간 / 십성 두 층 / 12운성).
  - "겉과 속이 다르다"는 말을 쓰려면 **표면 집계와 지장간 집계를 둘 다** 인용해야 한다.
  - 시주 미상이면 여섯 글자 한계를 한 번 밝히고, 시주 의존 판정(시지 십성 등)은 쓰지 않는다.
- **톤**
  - 팩폭 문단만 냥도사 말투(`~냥`) 1회 허용. 나머지는 해요체.
  - 호칭은 `{name} 님` 하나. "당신" 금지.
- **금지 규칙**
  - 신강·신약·용신·격국 확정.
  - "타고난 운명" 같은 결정론, "무조건", "100%".
  - 외모·체형·건강 단정.
  - 근거 없는 칭찬(바넘 문장) — 다른 명식에도 그대로 맞는 문장.

### 챕터 2. 반복되는 나의 패턴

- **무료 대비 새 정보**
  - 무료는 성향 3개를 **나열**한다. 유료는 그 3개가 **같은 축에서 반복**된다는 것을 보여 준다.
  - 반복이 과해질 때의 징후와, 끊는 순서(강도 낮추기보다 순서 바꾸기).
- **필요 입력**
  - 필수: `deukse.groupCountsByHiddenAll`, `tenGodFacts.byHiddenAll`, `deukji`(일지 운성·통근 등급), `period.daewoon`(천간/지지 십성), `period.seun`.
  - 선택: `FLAG.DOHWA`, `hapchong`(일지 충 축), `patterns` 카탈로그(폴백).
- **생성 조건**
  - 정확히 3축: ① 십성 묶음 ② 일주(일지) ③ 대운·세운 구간. 축마다 문단 1개.
  - 각 축에 "반복되는 장면 → 과해질 때 → 바꾸는 순서" 3요소 중 최소 2개.
  - 세 문단이 같은 문장 구조를 반복하면 반려(검증기 V12·judge).
  - 대운이 아직 없으면 ③을 "첫 대운 전"으로 바꾸고, 세운만으로 말한다.
- **톤**: 해요체. 훈계조("~해야 합니다") 금지, 제안은 "~해 보세요" 한 번까지.
- **금지 규칙**
  - 반복을 "운명"으로 만들지 않는다.
  - 같은 근거를 챕터 1과 다시 쓰지 않는다(챕터 간 중복 금지).
  - 대운·세운과 명식 글자의 합·충을 새로 만들지 않는다.

### 챕터 3. 사랑할 때의 나

- **무료 대비 새 정보**
  - 무료: 연애운 한 문단. 유료: **가까워지는 속도**, **끌리는 상대의 결**, **부딪히는 지점**, **그 지점이 드러나는 조건**.
  - 관계에서 쓰는 십성(관성·인성·식상)과 일지의 결을 연결.
- **필요 입력**
  - 필수: `tenGodFacts`, `deukji`(일지), `hapchong`(일지·월지 관계), `elementFacts`.
  - 선택: `period.seun`(올해 관계 구간 — 조건부로만), 궤도 Finding(상대 데이터가 있을 때만).
- **생성 조건**
  - 문단 2~3개: ① 가까워질 때의 방식 ② 끌리는 상대의 결 ③ 부딪히는 지점과 조건.
  - 상대를 특정하지 않는다. "이런 사람"은 **기운·방식**으로만 서술.
  - 결혼·임신·이별 시기를 확정하지 않는다. 시기는 "구간"으로만.
- **톤**: 담백하게. 과장된 로맨스 문구·미화 금지.
- **금지 규칙**
  - 상대 실명·나이·직업 단정.
  - 외모·성적 묘사.
  - 궁합 점수를 근거 없이 만들지 않는다(제품 규약 점수는 참고값이며 유료 궁합에서만).
  - "운명의 상대", "반드시 만난다".

### 챕터 4. 돈과 일, 나의 방식

- **무료 대비 새 정보**
  - 무료: 돈·일 각 한 문단. 유료: **돈이 들어오는 경로**(재성·식상·비겁의 배치), **새는 지점**, **맞는 환경/피할 환경**, **일하는 리듬**.
  - 관성(규칙·조직)과 인성(배움·보호)의 비중으로 환경 적합도를 나눈다.
- **필요 입력**
  - 필수: `deukse.groupCountsByHiddenAll`, `tenGodFacts`(두 집계), `elementFacts`, `deukryeong`, `geokguk.candidates`(일하는 방식 후보).
  - 선택: `period`(지금 구간의 재물·일 흐름 — 조건부), `saenggeuk`(제화가 있으면 "압박을 다루는 절차").
- **생성 조건**
  - 문단 3~4개: ① 들어오는 경로 ② 새는 지점 ③ 맞는 환경 ④ 피할 환경(또는 리듬).
  - 재성·식상·비겁 중 **실제로 있는 것만** 근거로 쓴다. 없는 십성을 "있다"고 하지 않는다.
  - 격 후보가 둘 이상이면 "일하는 방식의 후보가 둘"로 병기.
- **톤**: 실무적. 조언은 1문단에 1개까지.
- **금지 규칙**
  - 금액·수익률·확률·개월 수 창작.
  - 주식·코인·부동산 종목·매수 시점 권유.
  - "돈복이 없다/있다" 같은 단정, 사업 성공 보장.
  - 회사·직업명 단정("대기업이 맞다").

### 챕터 5. 지금 내 인생의 흐름

- **무료 대비 새 정보**
  - 무료: 올해 세운 한 줄. 유료: **지금 대운(10년)의 방식**, **올해 세운(1년)의 방식**, **두 방식이 겹치는 자리**, **다음 구간 준비**.
  - 대운 천간(바깥 방식)과 지지(안 방식)를 나눠 읽는 규칙(제품 해석).
- **필요 입력**
  - 필수: `period.daewoon`(간지·십성·나이 구간), `period.seun`, `period.daewoonStart`, `asOf`.
  - 없으면 비운다: 대운이 아직 없으면 `beforeFirstDaewoon` 으로 처리.
- **생성 조건**
  - 문단 2~3개. 시기를 확정하는 문장 금지, "구간의 방식"으로만.
  - 대운·세운 값은 **받은 것만** 인용. 다음 대운 간지를 추정하지 않는다.
  - 합·충은 `analysisData.hapchong` 에 있는 것만. 세운·대운과 명식의 합충은 엔진이 계산하지 않으므로 생성 금지.
- **톤**: 차분하게. 불안 조장 금지("큰일 난다", "조심해야 한다" 반복 금지).
- **금지 규칙**
  - "올해 안에", "반드시", "100%", "위험하다".
  - 건강·사고·이별 예고.
  - 대운 시작 나이 재계산.

### 챕터 6. 나와 주변 사람들의 인연

- **무료 대비 새 정보**
  - 무료: 없음. 유료: **일주 관계 유형**(같은 기운/귀인/기운을 빼앗김/눌림/내가 줌), **곁에 둘 기운**, **가까워질 때의 조건**.
  - 인연 지도(궤도)는 상대를 많이 넣을수록 정보가 늘지만, 상대 데이터는 일주 두 글자까지만 받는다.
- **필요 입력**
  - 내 쪽: `chart.pillars.day`(일주), `tenGodFacts`, `elementFacts`.
  - 상대: **일주 두 글자(일간·일지)만**. 없으면 이 챕터 생성 불가.
  - `P.compatibility`(제품 규약 점수·유형), `ORBIT.DAYREL.*`, `ORBIT.LIMIT.DAY_ONLY`.
- **생성 조건**
  - 상대별 2문단 이내. ① 관계 유형과 근거 ② 가까워질 때/부딪힐 때의 조건.
  - 상대가 일주뿐이면 **월지·연지·시주로 판정하지 않는다**는 한계를 문장에 남긴다.
  - 점수는 참고값으로만. "궁합 84점" 같은 숫자를 새로 만들지 않는다(제품 규약 값만).
- **톤**: 사람을 평가하지 않는다. "이 사람은 나쁘다" 금지.
- **금지 규칙**
  - 상대 실명·연락처를 출력·저장하지 않는다.
  - 상대의 성격·건강·재산 단정.
  - 네 기둥 판정(데이터가 없는데 있는 척).
  - 이별·배신 예고.

### 챕터 7. 냥도사의 천기부적

- **무료 대비 새 정보**
  - 무료: 없음. 유료: **명식이 각인된 이미지**(네 기둥·오행 5색 분포) + **개인화 한마디**.
  - 문구는 AI가 아니라 **코드가 고른 카탈로그**에서 나오고, AI는 후보 문구를 다듬는 역할만(선택).
- **필요 입력**
  - `chart.pillars`(네 기둥), `counts`/`share`(오행 5색), `dayMaster`, `free.bomb`(팩폭 1문장), 이름(마스킹된 호칭).
- **생성 조건**
  - 이미지: 1080×1920, 사주명식 네 기둥 + 오행 누적 띠 + 개수%, 서명 `{name} 님의 천기 부적 · 냥도사`.
  - 문구: 20자 이내 1문장. 팩폭과 같은 근거를 쓰되 같은 문장을 반복하지 않는다.
  - 생년월일은 이미지에 넣지 않는다(현재 제품 규칙).
- **톤**: 단정적이되 위협적이지 않게. 부적은 상징이며 효능 보장이 아니다.
- **금지 규칙**
  - 효능 보장("이 부적을 가지면 재물이 들어온다").
  - 건강·수명·재난 예고.
  - 미신적 공포 조장, 결제 유도 문구 삽입.

## 3. 공통 규칙 (7챕터 전부)

| 항목 | 규칙 |
|---|---|
| 근거 | 문단마다 `evidenceRefs` ≥1. D/E 는 섹션마다 `kbRefs` ≥1 |
| 사실 계산 | 간지·십성·합충·대운은 코드가 계산한 것만. 창작 금지 |
| 수위 | neutral 판정을 긍정/부정으로 바꾸지 않는다 |
| 상충 | 양립하는 두 판독이 있으면 양쪽 + 조건 |
| 개인화 | 다른 명식에도 맞는 문장 금지. 문단마다 그 사람의 사실 ≥1 |
| 숫자 | 확률·점수·퍼센트·개월 수 창작 금지. 사실에 있는 값만 |
| 단정 | "반드시·100%·틀림없이·확실히·절대로" 금지 |
| 민감 | 의료·법률·투자·생사 판정 금지 |
| 개인정보 | 이름·생년월일·전화·지역을 출력에 쓰지 않는다(호칭은 `{name} 님`) |
| 길이 | 챕터당 2~5문단, 문단 80~340자 |
| 폴백 | 검증 실패 시 규칙 카탈로그 문장으로 대체. 화면에 실패를 티내지 않는다 |

## 4. 생성 파이프라인

```text
생년월일시
  └─(코드) 만세력 → 명식 → analysisData → Finding
        └─(코드) 8섹션 그릇 + 프롬프트(B/C/D/E 중 선택)
              └─(AI) 8섹션 문단 + 근거 ID
                    └─(코드) 검증기 V1~V15 → 실패 시 피드백 재시도 → 그래도 실패면 규칙 폴백
                          └─(코드) 7챕터 조립 + 부적 이미지
```

- 챕터 6(인연)은 8섹션 밖에서 궤도 Finding으로 조립한다.
- 챕터 7(부적)은 AI 없이도 완성된다(코드 카탈로그).
- 유료 1회 생성 = 8섹션 1회 호출(청크 분할 시 2~3회). 비용은 `tests/ai-compare/lib/cost.mjs` 로 계측.

## 5. 실험과의 연결

- `--mode full`(QA01~12)에서 나온 8섹션 결과를 위 표대로 조립해 **7챕터 초안**을 만든다.
- 챕터별 품질은 8섹션 지표로 대신 본다(현재 하네스 범위).
  - 챕터 1 ← §01·§02
  - 챕터 2 ← §04
  - 챕터 3 ← §05(+§03 조건)
  - 챕터 4 ← §06·§07
  - 챕터 5 ← §08
  - 챕터 6 ← 궤도(별도)
  - 챕터 7 ← 코드
- 챕터 단위 채점(사람 평가)은 블라인드 패키지(`out/<runId>/blind/`)로 한다.

## 6. 아직 정하지 않은 것

| 항목 | 상태 | 결정이 필요한 이유 |
|---|---|---|
| 챕터별 분량·가격 | 미정 | 7챕터를 1,900원 단일 결제에 담을지, 챕터 묶음 판매할지 |
| 챕터 6의 상대 입력 범위 | 미정 | 일주 2글자만 받으면 정확도가 낮고, 4주를 받으면 개인정보 위험 |
| 챕터 7의 AI 개입 여부 | 미정 | 문구 개인화를 AI로 하면 비용·검증 부담, 코드로 하면 안전 |
| 챕터 간 중복 허용치 | 미정 | 같은 근거를 다른 챕터에서 다시 쓰는 것을 어디까지 허용할지 |
| 무료→유료 전환 카피 | 미정 | 각 챕터 첫 문단에서 무료와 무엇이 다른지 한 줄 안내할지 |
